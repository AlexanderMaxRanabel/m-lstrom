START HERE — M0, in this order (all small, each unblocks a stable Complement test)
  1. Router fallbacks — crates/maelstrom-api/src/router.rs
     No .fallback() / .method_not_allowed_fallback() exists, so unknown paths
     return an empty-body 404 and wrong methods an empty-body 405. The spec and
     Complement (tests/csapi/unknown_endpoints_test.go) require
     {"errcode":"M_UNRECOGNIZED"} with 404 / 405.
     CAREFUL: M_UNRECOGNIZED currently maps to 400 in
     crates/maelstrom-core/src/matrix/error.rs:144-150 — fix that in the same
     change or the fallback will emit the wrong status code.
  2. Close the auth hole — crates/maelstrom-api/src/handlers/appservice.rs:48-71
     POST/GET/DELETE /_maelstrom/admin/v1/appservice[s] sit in the CLIENT router
     with no admin check. Move them to crates/maelstrom-admin or add AdminUser.
  3. versions.rs — add "v1.19"; UnstableFeatures is an empty struct, it must become
     serde_json::Map<String, bool> and list the MSCs actually implemented
     (msc3967, msc3706, msc4102, msc4186, msc3391) or those implementations go.
  4. Error bodies — 11 handlers use raw axum::Json, so a bad body yields a
     plain-text 400 instead of M_BAD_JSON. The repo already has the right
     extractor: crates/maelstrom-api/src/extractors/json.rs (MatrixJson).
  5. Path aliases that unblock stable tests:
       GET /_matrix/client/v1/rooms/{roomId}/timestamp_to_event
         (only the v3 path exists today — handlers/events.rs:129)
       GET /_matrix/client/v1/room_summary/{roomIdOrAlias}   (does not exist)
       GET /_matrix/client/v3/pushrules/global/              (does not exist)

THEN THE CRITICAL PATH (M2, M3) — both are security blockers
  M2 Authorization rules. Maelstrom currently has almost none:
        - kick/ban/unban have NO power-level check -> any member can ban anyone
          (handlers/rooms.rs:1256-1427)
        - a user's own m.room.member event bypasses all checks
          (handlers/events.rs:705-753)
        - no m.room.power_levels change rules -> a PL-50 user can rewrite PL to 100
          (handlers/events.rs:710-753)
        - invite has no invite-level / target-ban check
          (handlers/rooms.rs:1093-1204)
        - events_default never applied to non-state events
          (handlers/events.rs:148-233)
      Deliverable: ONE shared room-version-aware auth_rules module, used by both
      the CS API and the federation receiver.
  M3 Federation. Locally created events are never signed and carry no
      prev_events/depth/origin/hashes/signatures (handlers/events.rs:187 and
      friends) — Pdu::sign() has zero call sites, so real servers reject every
      outbound PDU. Inbound PDU auth is soft-fail (federation/receiver.rs:496,
      516, 566) and X-Matrix signature failures are only logged
      (receiver.rs:177, 214). resolve_state is not state res v2
      (core/matrix/state.rs:90).
      Deliverable: one create_event() helper that signs, a real auth check on
      inbound, and state res v2.

RULES OF THE REPO (from VERIFICATION.md and the code)
  - Tests live in tests/, never inline in source files. One file per area.
  - cargo fmt + cargo clippy must be clean; CI runs with RUSTFLAGS=-Dwarnings.
  - cargo test must pass before running Complement.
  - Always RecordId::new() for SurrealDB record ids. Never type::thing(), never
    split strings by hand.

  - Never change the require_membership fallback — departed users depend on it.
  - Do not speculatively rewrite working handler behaviour; add new paths, keep the

    storage/mock, or the mock-based tests break.
  - Structured logging via tracing, never println!.
